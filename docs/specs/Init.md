**# **Технічна специфікація: Інтеграція Skedda Scheduler для Home Assistant**

Цей документ містить вичерпні технічні вимоги та архітектурну специфікацію для розробки кастомної інтеграції Home Assistant (skedda\_scheduler). Інтеграція призначена для автоматизації бронювань кортів/майданчиків у сервісі Skedda, управління декількома акаунтами, синхронізації з Google Calendar та наочного відображення розкладу через стандартні UI-компоненти Home Assistant.

## **1\. Основні вимоги та користувацький досвід (UX)**

> * **Установка без додаткового налаштування ("Без танців з бубном"):** Повна підтримка HACS (Home Assistant Community Store) як кастомний репозиторій. Установка в один клік через UI.  
> * **Налаштування через UI (Config Flow / Options Flow):** Відсутність необхідності редагувати configuration.yaml. Усі акаунти, правила та автоматизації налаштовуються виключно через інтерфейс Home Assistant.  
> * **Управління декількома акаунтами Skedda:** Можливість додавати декілька облікових записів (наприклад, власний та акаунт партнера) з можливістю прив'язки конкретного акаунту до кожного окремого завдання бронювання.  
> * **Автономність та стабільність:** Робота через прямі HTTP/REST запити до приватного API Skedda (без сумісності з Selenium/Puppeteer), підтримка авто-повторів (retry logic) при мережевих збоях.

## **2\. Архітектура компонента Home Assistant**

Структура директорії інтеграції custom\_components/skedda\_scheduler/:

| Файл | Призначення   |
| :---- | :---- |
| manifest.json | Опис інтеграції (версія, назва, HACS сумісність, залежності). |
| config\_flow.py | Покроковий майстер налаштування (додавання акаунтів, створення та редагування завдань через UI). |
| \_\_init\_\_.py | Ініціалізація компонента, завантаження та збереження конфігураційних записів (ConfigEntries). |
| skedda\_api.py | Асинхронний Python-клієнт (aiohttp) для взаємодії з приватним REST API Skedda. |
| coordinator.py | DataUpdateCoordinator для періодичного оновлення стану акаунтів та майбутніх бронювань. |
| calendar.py | Створення сутності Календаря HA для відображення запланованих автоматизацій у Lovelace UI. |
| sensor.py | Сенсори стану акаунтів (активний/помилка авторизації) та статусу виконання бронювань. |
| services.yaml | Опис кастомних сервісів HA (наприклад, skedda\_scheduler.trigger\_job\_now). |

## **3\. Модуль авторизації та мульти-акаунтів (Config Flow)**

Інтеграція підтримує додавання декількох записів (Integration Entries). Кожен запис відповідає за окремий акаунт Skedda або окрему групу автоматизацій.

### **Процес додавання акаунту (Step User):**

> 1. Користувач вказує Subdomain Venue Skedda (наприклад, myclub для myclub.skedda.com).  
> 2. Вводить Email та Пароль акаунту Skedda.  
> 3. Вказує зрозумілий псевдонім акаунту (Alias), наприклад: *"Основний акаунт (Олег)"*.  
> 4. Система перевіряє авторизацію через API запит. У разі успіху дані зберігаються в зашифрованому сховищі Home Assistant.

## **4\. Специфікація робіт з приватним API Skedda**

Основні ендпоінти та алгоритми роботи клієнта skedda\_api.py:

POST https://{venue}.skedda.com/api/account/login  
Payload: {"email": "...", "password": "..."}  
Response: Set-Cookie (.AspNetCore.Identity.Application) / Bearer Token

GET https://{venue}.skedda.com/api/spaces  
Response: Список кортів, їхні spaceId та параметри доступності.

POST https://{venue}.skedda.com/api/bookings  
Payload:  
{  
  "spaceIds": \[10293\],  
  "start": "2026-05-19T18:00:00.000Z",  
  "end": "2026-05-19T19:30:00.000Z",  
  "title": "Теніс (Автобронювання)",  
  "lockState": "Locked"  
}

## **5\. Двигун планових завдань та повторюваності**

Кожне автоматичне бронювання створюється через Options Flow як окремий об'єкт зі своїми параметрами:

| Параметр | Опис та приклад   |
| :---- | :---- |
| **Назва завдання** | Вівторок 18:00 (Вечірнє тренування) |
| **Обраний акаунт** | Вибір з раніше доданих акаунтів (наприклад, "Основний" або "Акаунт 2") |
| **День тижня та Час** | Вівторок, 18:00 (Тривалість: 90 хв) |
| **Основний та резервний корт** | Space ID №1 (Основний), Space ID №2 (Якщо основний зайнятий) |
| **Діапазон відкриття вікна** | За скільки днів/годин відкривається бронювання (наприклад, за 7 днів о 00:00:01) |
| **Правила повторюваності** | Періодичність: Щотижня / Через тиждень; Дата початку та закінчення сезону |
| **Інтеграція з Google Calendar** | Вказується calendar\_entity та список email учасників для відправки запрошень |

## **6\. Інтеграція з Google Calendar та Сповіщення**

При успішному підтвердженні бронювання від Skedda API виконуються наступні дії:

> 1. Формується запит до сервісу calendar.create\_event у Home Assistant.  
> 2. У події вказуються назва, час початку/завершення, опис із зазначенням ID бронювання та список учасників (Inbound Attendees).  
> 3. Усі учасники отримують стандартне запрошення від Google Calendar з можливістю додати подію в один клік.  
> 4. Відправляється сповіщення в Telegram / HA Mobile App з результатом виконання та посиланням на подію.

## **7\. Відображення в Календарі Home Assistant (calendar.py)**

Компонент розгортає сутність calendar.skedda\_schedule. Вона розраховує та візуалізує майбутні автобронювання на тиждень та місяць вперед у виді кастомних подій. Це дозволяє користувачеві наочно бачити розклад та контролювати черговість бронювань між різними акаунтами.**
